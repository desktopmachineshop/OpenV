# Refactor tools

Tools that prove a refactor changed nothing it should not have. They belong
to step S14a of the refactor plan (`docs/plans/codebase-refactor.md`) and
back its verification classes (§4.2): class **A** (pure move) is proved by
`declhash` and `tsmovecheck`, generated by `declmove`, and reviewed from the
`movecheck` map; class **B** boot stages (M4) are checked with
`movecheck -flatten`. Each Go tool is a stdlib-only `package main`, run with
`go run` from the repository root; none touches `go.mod`.

The three Go tools share `decls.go` byte for byte (the S1 architecture test
freezes the module's import edges, so they cannot import a common package);
`declhash`'s `TestSharedFileIsIdentical` keeps the copies equal. Edit
`declhash/decls.go` and copy it over the other two.

## declhash

```
go run ./internal/tools/declhash [-o manifest] [-tests=false] <pkg dir>...
go run ./internal/tools/declhash -compare base.txt head.txt
go run ./internal/tools/declhash -base <git-ref> [-head <git-ref>] <pkg dir>...
```

Hashes every package-level declaration: functions, methods (`(*T).Name`,
`T.Name`), types, vars and consts, one entry per name of a grouped spec (a
const keeps its implicit type and value, and its iota when it uses iota).
The hash covers the go/printer rendering with doc and inner comments, the
file's build constraints, and the import path behind each package
qualifier; file names and import blocks are not part of it, so moving
declarations between files leaves the manifest identical. `-base` compares
a git ref with the working tree (or `-head`) without checking anything out
and exits 1 on any added, removed or changed declaration. Used by every
class-A step, per commit (M1, M5–M9, M10's and M11a's move commits, M12),
and by the S14b guard job.

## declmove

```
go run ./internal/tools/declmove [-n] [-goimports=false] -spec internal/tools/declmove/specs/<step>.json
```

Moves declarations between the files of one package as a committed spec
says, keyed by declhash name (rule R4: a move PR is regenerated on the
latest master, never rebased). Each declaration moves with its doc comment,
in spec order; a new target file gets the spec's header comment and the
package clause. The moved code takes its imports with it, sources drop the
imports only it used, an emptied file is deleted, and the pinned goimports
(`golang.org/x/tools/cmd/goimports@v0.42.0`, one constant in `main.go`)
tidies the touched files. It refuses a missing or ambiguous name (pick a
duplicate with `Name#2`) and a grouped declaration that is not moved whole,
then checks its own result: the package's declhash manifest must be
unchanged, or every file is restored. `-n` prints the moves only.
`specs/example.json` shows the format (the shape of M1's move commit). Used
by M1, M5–M9 and M12; the spec goes in the PR.

## movecheck

```
go run ./internal/tools/movecheck [-tests] [-head <ref>] <pkg dir>
go run ./internal/tools/movecheck [-tests] -base <ref> [-head <ref>] <pkg dir>
go run ./internal/tools/movecheck -flatten <func> [-recv a] [-base <ref>] <pkg dir>
```

Prints the declaration-to-file map (`key -> file.go`), or with `-base` only
what changed file (`key: old.go -> new.go`): the map a move PR's
description carries (§6.5) and a hot-file window announces (§6.9).
`-flatten main` prints `main()` with every `a.<stage>()` call inlined from
the `wire_*.go` stage methods, and fails if a stage contains `defer`,
`recover` or a return before its last statement; with `-base` it prints a
diff of the flattened statements against the ref. Used by M4 (with S14c's
`stageextract`), and by M6–M9 for their maps.

## frontend/scripts/tsdeclhash.mjs

```
node frontend/scripts/tsdeclhash.mjs [--root dir] [--no-module] [-o manifest] [path...]
node frontend/scripts/tsdeclhash.mjs --compare base.txt head.txt
node frontend/scripts/tsdeclhash.mjs --base <ref> [--head <ref>] [--no-module] [path...]
```

The TypeScript counterpart of declhash, over `frontend/src` by default: one
entry per top-level declaration (`module<TAB>name<TAB>sha256`), imports and
export wiring excluded. A hash covers the text with its attached comments
and what each module-level name it uses is bound to, by content, so a
moved dependency still matches and a rebinding does not. `--no-module`
compares declarations wherever they live, as F1 needs.

## frontend/scripts/tsmovecheck.mjs

```
node frontend/scripts/tsmovecheck.mjs [--root dir] [--head <ref>] <base-ref> [path...]
```

Fails unless the only differences from the base ref are wiring (imports,
re-exports, export lists) and declarations that moved between modules
unchanged; prints each move. Used by F1 and any class-A TS move. Both
scripts use `frontend/node_modules/typescript` (run `npm ci` first); their
tests run with `cd frontend && node --test 'scripts/*.test.mjs'`.

## scripts/refactor/classify_commits.py

```
python3 scripts/refactor/classify_commits.py [-n N] [--first-parent] [--json] [--files] [REV...]
```

Classifies commits by the layers they touch (migration/schema, repository,
domain, handler, route registration, main wiring, frontend client, types,
views/components, CSS, tests, docs, release notes, and the rest), with
files per commit and the hub-touch rate over the five hub files. It
measures the plan's success metrics (§10) before and after.

## make check and make check-fast

`make check` runs CI's pull-request gates locally (gofmt, vet, test, the
release-notes checks, tsc, lint, vitest, build) plus the tests above that
live outside Go. `make check-fast` is the under-a-minute loop: gofmt, vet,
`go test -short` on the packages changed since `BASE_REF`
(`origin/master`), and tsc.
