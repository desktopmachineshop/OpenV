# Environment variables

Every environment variable OpenV's Go programs read: the API server
(`cmd/server`, *server* below), the runner (`cmd/agentd`, *agentd*) and the
MCP server the runner hands each agent (`cmd/openv-mcp`, *openv-mcp*). Each
has a line saying which area of the product it belongs to (the areas of
[`areas.json`](areas.json)), what reads it, its default and what it does.
How to run a deployment with them is [operations.md](operations.md) and, on
Railway, [railway.md](railway.md); the runner's own settings are in
[agents.md](agents.md).

## How the list is kept true

The tables below are generated, and a test holds them to the code:

- The **names**, and every default the code passes as a constant, come from
  the inventory of refactor step S8,
  [`internal/archtest/testdata/env_vars.txt`](../internal/archtest/testdata/env_vars.txt),
  which `TestEnvInventory` keeps equal to what the code reads: it fails on
  a read it cannot name.
- **What each one does**, its area, what reads it and the defaults the
  inventory cannot see (a fallback the code computes, the inline default of
  a direct read) come from
  [`internal/tools/envdoc/vars.json`](../internal/tools/envdoc/vars.json).
- `go run ./internal/tools/envdoc` rewrites the tables from those two files
  and leaves the rest of this page alone. `TestEnvVarsDoc`
  (`internal/tools/envdoc/envdoc_test.go`) fails when a name the code reads
  is missing here, when a name listed here is no longer read, or when the
  tables are not what the generator writes.

So a new setting is three edits: the read in the code (regenerate
`env_vars.txt` as `internal/archtest/README.md` says, which is a behaviour
change with a release note), its entry in `vars.json`, and the generator's
run.

## How a value is read

The server and the runner read every setting by one rule
(`internal/envparse`; [operations.md](operations.md#how-a-setting-is-read)
has the detail). A value is trimmed, and one of only spaces counts as unset.
A count (a burst, a size in MB, a concurrency) is a whole number above 0,
and a size in MB at most 8796093022207, the largest whose count of bytes
fits in a 64-bit integer; a duration is a positive Go duration (`90m`,
`24h`, not `30d`); a rate, a `…_REFILL_PER_HOUR`, is a positive, finite
number; an on/off setting is `true` or `false` in any case, or `1` or `0`,
and a switch documented as `=off`, `OPENV_UPLOAD_SWEEP`, also takes `on` or
`off` in any case, while `HOSTED_RUNNERS` and `OPENV_EMAIL_VERIFICATION`
take only `off`. A
value that breaks its rule
keeps the default, and the log names the variable once, never its value.
The exceptions are named in their lines: the billing counts and
`OPENV_LIMITS`, `OPENV_STRIPE_PRICES`, `OPENV_BILLING_GRANDFATHER_BEFORE`
and `DATABASE_URL` stop the server when malformed, `HOSTED_RUNNER_PIDS_LIMIT`
reads `0` as no cap, and a credential is used exactly as set, never trimmed,
with a warning naming it when spaces or a line break sit around it.

A rate limit is a token bucket: the `…_BURST` is how many requests may come
at once, and the `…_REFILL_PER_HOUR` how fast the bucket fills again. The
buckets live in the API process, so they assume a single API instance.

## Read elsewhere

The inventory reads this module's Go code, so it does not see these:

- **The frontend image** (nginx, `frontend/docker-entrypoint.d/`):
  `API_UPSTREAM`, the API's `host:port` on the private network that `/api/`
  is proxied to (default `api:8080`); `OPENV_NOINDEX`, set to keep a
  deployment out of search results; `OPENV_APP_VARIANT=staging`, the
  installed app's name and icons for staging; and, at build time only,
  `REACT_APP_API_URL`, the API origin of a split deployment, where the
  browser does not go through the proxy.
- **Compose files**: `POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB`
  for the database container, `FRONTEND_PORT`, and the backup service's
  `BACKUP_*` settings ([operations.md](operations.md#scheduled-backups)).
- **Libraries and the Go runtime**: the database driver's `PG*` variables,
  Docker's client settings (`DOCKER_HOST` and its companions) for hosted
  runners, the proxy variables (`HTTPS_PROXY`, `NO_PROXY`) for outbound
  calls, and `XDG_CONFIG_HOME` (through `os.UserConfigDir`), where the Agent
  Connector keeps its state. Their defaults are the libraries'.
- **Scripts**: `scripts/openv/sync.py` reads `OPENV_API_URL`,
  `OPENV_API_TOKEN` (a workspace runner key), `OPENV_EMAIL` and
  `OPENV_PASSWORD` (only `register` and `bootstrap` need an account),
  `OPENV_WORKSPACE` and `OPENV_PROJECT`.
- **Tests**: `OPENV_TEST_DATABASE_URL` points the Postgres tests at a
  server; `UPDATE_GOLDEN`, `UPDATE_ROUTES` and `UPDATE_RATCHETS` regenerate
  goldens and ratchets (`CONTRIBUTING.md`); `ENV_INVENTORY_REPORT` writes the
  inventory's report of where each read sits.
